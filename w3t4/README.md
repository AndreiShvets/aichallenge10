# w3t4 — инварианты задачи

Продолжение [w3t3](../w3t3/README.md): у задачи есть инварианты, которые сохраняются отдельно от диалога и учитываются при формировании ответа. Перед показом ответа отдельный вызов модели проверяет его на соответствие действующим правилам.

## Запуск

```powershell
python .\w3t4\main.py
python .\w3t4\main.py --provider veai --model openai/gpt-4o-mini
```

Профили, явное переключение задач и автомат состояний описаны в [w3t3](../w3t3/README.md). Инварианты принадлежат задаче внутри профиля; при возврате к архивной задаче её инварианты действуют снова.

## Управление

```text
/invariant list
/invariant add Использовать только стандартную библиотеку Python.
/invariant add Не предлагать хранить пароли в открытом виде.
/invariant replace 1 Использовать только стандартную библиотеку Python 3.10+.
/invariant remove 2
```

`add` присваивает ID, `replace` меняет правило с указанным ID, `remove` удаляет его. Все изменения записываются вместе с предыдущим и новым значением и временем в `profiles/<имя>/invariants.json`. Из обычного диалога правила не меняются. Файл отделён от истории диалога; повреждённый файл не заменяется пустым набором и блокирует работу.

## Проверка ответа

При действующих инвариантах агент получает их вместе с запросом. Ответ до показа проверяется отдельным вызовом модели без истории и инструментов. Если проверяющий выявил конфликт, пользователь получает отказ с перечислением правил; исходный ответ не показывается и не сохраняется в историю. При ошибке, обрезанном или неразборчивом ответе проверяющего ответ тоже не выдаётся. Каждый обычный ответ с инвариантами требует как минимум два запроса к модели — генерацию и проверку, помимо возможных служебных вызовов.

Модельная проверка **вероятностна**: проверяющий может ошибиться или поддаться подмене инструкций. Поэтому это не формальная гарантия, что любое нарушение будет обнаружено. Инструменты в обычном цикле при действующих правилах отключены, чтобы исключить их выполнение до проверки ответа. HTTP-логирование генерации и проверки при действующих правилах отключено. Команды `/fill`, `/check`, `/cleanup`, `/personal-test` и `/invariant-test` при активных правилах недоступны: их ответы иначе обходили бы проверку действующих инвариантов. Очистка `/clear-layer work` запрещена, если есть история инвариантов: это предотвращает повторное использование номеров задач.

## Опыт с попытками обхода

Команда `/invariant-test` запускает изолированный опыт со своим правилом про стандартную библиотеку и восемью разными попытками предложить `requests`. Перед началом нужно подтвердить платный прогон: до 16 запросов к модели, без учёта возможных накладных расходов провайдера. Опыт доступен, только когда у текущей задачи нет активных инвариантов, и не изменяет их.

Отклонённый проверяющим ответ считается не прошедшей попыткой. Каждый выданный ответ оценивается вручную: нарушает правило, не нарушает или оценка неопределённа. Ошибки проверки учитываются отдельно, а не считаются успешным обходом. Полные выданные ответы, вердикты, оценки и подсчёт сохраняются в JSON и CSV в корне репозитория. Проверка на заглушках не подтверждает устойчивость реальной модели.
