# w1t4 — влияние температуры на ответы модели

Продолжение [w1t3](../w1t3): там сравнивались модели и способы решения, здесь —
насколько ответы **одной** модели зависят от температуры сэмплирования. Одна
выбранная модель на температурах 0, 0.7 и 1.2 отвечает на два запроса по пять раз,
после чего программа считает, насколько отличаются ответы внутри каждой пятёрки.

## Что запрашивается

Два запроса, оба выбираются при запуске:

| Тип | Что это | Что измеряем |
|---|---|---|
| с единственным правильным ответом | задача, у которой есть один эталон | долю верных и число разных ответов в пятёрке |
| творческий | название продукта или короткое объявление | насколько тексты отличаются друг от друга |

Готовые варианты точного запроса — средняя скорость на равных участках пути
(48, ловушка «50»), нули в 25! (6), совпадения стрелок (22). Готовые творческие —
название и объявление для приложения, которое по фото холодильника подсказывает,
что приготовить. Вместо любого готового варианта можно ввести свой запрос
(для точного — вместе с эталонным ответом).

Порядок прогона: температура → запрос → 5 повторов подряд.

## Метрики различия

Считаются по каждой пятёрке отдельно, то есть 3 температуры × 2 запроса = 6 наборов.

| Метрика | Смысл | Где |
|---|---|---|
| Верных | сколько ответов совпало с эталоном | точный |
| Уникальных | сколько разных ответов было извлечено | точный |
| Сходство ср. / мин. | средняя и худшая попарная косинусная близость ответов | оба |
| Жаккар | среднее пересечение множеств слов двух ответов | оба |
| distinct-2 | доля уникальных биграмм от их общего числа: 1.00 — все формулировки разные | творческий |
| Совпадение первого ответа | сколько повторов дали одинаковый первый результат (название/первую строку) | творческий |
| Длина ср., min–max | длина ответа в символах | творческий |
| Повторы дословно | группы полностью совпадающих ответов, например `×3, ×2` | творческий |

Сходство считается на частотных векторах слов с весами IDF по паре документов —
это TF-IDF без внешних библиотек. 1.00 означает дословное совпадение, 0 — нет ни
одного общего слова. Значения по паре берутся как среднее по 10 парам (для пятёрки)
и как минимум: минимум показывает, насколько разными вышли самые непохожие два ответа.

### Общее сходство и смысл: чем метрики не равны

Лексические метрики штрафуют пересказ одной и той же идеи другими словами
и завышаются общими словами запроса. Поэтому для творческого запроса дополнительно
печатается повторяемость первого результата: для названия это само название,
для объявления — первая строка. Совпадение этих ячеек — честный признак того,
что модель выдала один и тот же вариант, а не перефразировала его.

Ручная оценка ответов не производится: все метрики считаются автоматически
и воспроизводятся по сохранённому JSON.

## Запуск

```powershell
python .\w1t4\main.py
```

Флаги:

| Флаг | Действие |
|---|---|
| `--temps 0,0.7,1.2` | список температур (0–2, через запятую) |
| `--repeat 5` | сколько повторов на температуру (1–20) |
| `--env PATH` | файл с ключами |
| `--no-cache` | переавторизоваться в GigaChat |

Ключи берутся из того же `.env`, что и в прошлых задачах: `GIGACHAT_CREDENTIALS`
и `VEAI_CREDENTIALS`. Файл ищется от папки задачи вверх по дереву каталогов.

## Вывод

1. **Все ответы** — по каждому запросу и каждой температуре печатаются все
   повторы целиком: полный текст ответа без обрезки, с пометкой `+`/`−`
   для точного запроса. Во время прогона тоже печатается весь ответ, а не начало.
2. **Сводка различия** — таблица по температурам: для точного запроса
   верные и уникальные ответы, для творческого сходство, distinct-2 и
   повторяемость первого ответа; отдельно — длины и дословные повторы.
3. **Токены и время** — расход по температурам.
4. **Экспорт** — файлы `w1t4_<модель>_<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>` в корне проектов
   (рядом с `tasks.json`):

| Файл | Содержимое |
|---|---|
| `.json` | `meta` (провайдер, модель, температуры, тексты запросов, итоги), `dispersion` (метрики по каждой температуре) и `results` (все повторы с полными текстами ответов) |
| `.csv` | те же строки для Excel: разделитель `;`, кодировка `utf-8-sig`, переводы строк в ответах схлопнуты |

Сырые ответы сохраняются целиком, поэтому метрики можно пересчитать по JSON,
не тратя запросы повторно.

## Ограничение, без которого выводы неверны

**`temperature=0` не гарантирует детерминизм.** API считает распределение
и при нулевой температуре может выбирать из него (например, при батчинге
или округлении логитов), а некоторые модели вообще игнорируют параметр. Поэтому
пятёрка при 0 — это не «эталон без разброса», а проверка остаточной
неопределённости провайдера. Если сходство при 0 близко к 1.00, это подтверждает,
что рост разброса при 0.7 и 1.2 — следствие температуры, а не свойства модели.

Для Veai в списке моделей помечаются те, у которых каталог не заявляет
`temperature`: запросы к ним уйдут без параметра, и разница температур может
не проявиться. При выборе такой модели выводится предупреждение, а в JSON
пишется `temperature_supported: false` и `temperature_limitation`.

## Стоимость прогона

3 температуры × 2 запроса × 5 повторов = **30 запросов**. На Veai это минуты
подписки, и прогон занимает несколько минут реального времени. Для быстрой
отладки — `--temps 0,1.2 --repeat 2` (4 запроса на каждый запрос), для этого же
используйте GigaChat: ответ идёт 0.1–5 с вместо 4–20 с у Veai.

## Отличия от w1t3

* Клиенты GigaChat и Veai — копия из [w1t3](../w1t3) с добавленным параметром
  `temperature` (передаётся, только если задан: `0.0` — валидное значение,
  и проверка `if temperature` его бы потеряла).
* Вместо набора задач из `tasks.json` — два запроса, выбранных или введённых
  вручную; вместо `reasoning_effort` — `temperature`.
* Вместо проверки правильности одного ответа — метрики сходства внутри пятёрки
  одинаковых запросов.
