# w1t3 — сравнение моделей и способов решения задач

Продолжение [w1t2](../w1t2): там был один запрос с параметрами, здесь — замер
качества. Одна выбранная модель GigaChat или Veai решает набор задач при двух
уровнях рассуждений четырьмя разными способами, результаты сводятся в таблицу.

## Наборы задач

Задачи лежат в корне проектов, чтобы файлы переиспользовали следующие задачи.

| Файл | Задач | Назначение |
|---|---|---|
| [`tasks.json`](../tasks.json) | 12 | полный набор |
| [`tasks_short.json`](../tasks_short.json) | 7 | сокращённый набор для быстрой проверки |

Сокращённый набор покрывает все четыре темы и обе части шкалы сложности
(4–9) и включает самые разделяющие модели задачи: совпадения стрелок,
нули в факториале, средняя скорость на равных участках, включения множеств,
проходы пузырьковой сортировки, 3^100 mod 1000.

У задачи есть поля: `id`, `topic`, `difficulty` (1–10), `answer_type`
(`int` или `word`), `answer`, `accepted` (допустимые написания), `question`,
`explanation` (как получен эталон).

## Как сравниваются модели

Каждая задача решается за **2 уровня рассуждений × 4 способа** = 8 запросов,
плюс 2 отдельных запроса, в которых модель составляет для себя промпт:

| Способ | Что уходит в модель |
|---|---|
| напрямую | текст задачи как есть |
| решай пошагово | задача + требование подробно рассуждать по шагам |
| промпт от модели | сначала запрос «составь промпт для решения такой задачи» (без решения), затем этот промпт + задача |
| группа экспертов | задача в роли аналитика, инженера и критика с согласованием итогового ответа |

Уровни рассуждений передаются параметром `reasoning_effort`:

| Уровень | Veai | GigaChat |
|---|---|---|
| низкий | `low` | `low` |
| максимальный | `max` | `high` |

GigaChat принимает только `low`/`medium`/`high`, на `max` отвечает
`HTTP 422 Unknown reasoning_effort`, поэтому максимальный уровень у него — `high`.
Модели Veai без поддержки `reasoning` (`Anthropic/haiku-4.5`,
`Google/gemini-3.5-flash-lite`) параметр игнорируют.

## Как проверяется ответ

Автоматически, без модели-судьи:

1. из ответа извлекается число (сначала по словам-подсказкам «Ответ», «итого»,
   «равно», иначе — последнее число) или вариант из `accepted`;
2. для чисел требуется точное совпадение с эталоном; для слов — совпадение
   с `answer` или любым вариантом из `accepted` без учёта регистра, ё/е,
   пробелов, дефисов и пунктуации.

## Запуск

```powershell
python .\w1t3\main.py
```

При запуске программа спрашивает, какой прогон запускать:

```
Какой прогон запускать?
  1. сокращённый — 7 задач, быстрый (tasks_short.json)
  2. полный — 12 задач, долгий (tasks.json)
  Enter — полный набор
```

Пустой ответ — полный набор. Прогон спрашивается до запросов к API,
чтобы не тратить минуты подписки зря.

Флаги (позволяют не отвечать на вопрос):

| Флаг | Действие |
|---|---|
| `--short` | сокращённый набор |
| `--full` | полный набор |
| `--tasks PATH` | произвольный файл задач |
| `--env PATH` | файл с ключами |
| `--no-cache` | переавторизоваться в GigaChat |

Ключи берутся из того же `.env`, что и в прошлых задачах:
`GIGACHAT_CREDENTIALS` и `VEAI_CREDENTIALS`.

## Выбор модели и пометки

В списке моделей рядом с теми, на которых **нельзя провести полноценный тест
по уровню рассуждений**, пишется причина:

```
  1. Anthropic/haiku-4.5 (не поддерживает уровни рассуждений: оба уровня пойдут одним запросом)
  2. Anthropic/haiku-5.5
  …
 13. Google/gemini-3.5-flash-lite (не поддерживает уровни рассуждений: …)
```

Помеченные модели выбрать можно — но при выборе выводится предупреждение,
в шапке итогового отчёта повторяется причина, а в JSON-файле пишутся поля
`reasoning_levels_comparable: false` и `reasoning_limitation`.

Что именно помечается:

| Провайдер | Пометка |
|---|---|
| GigaChat | все модели: `уровень рассуждений не влияет на ответ` (`reasoning_effort` принимается, но ответ не меняется) |
| Veai | модели без `low`/`max` в `reasoning.supported_efforts` — сейчас это `Anthropic/haiku-4.5` и `Google/gemini-3.5-flash-lite` |

Остальные 33 модели Veai поддерживают оба уровня, поэтому у них пометки нет.

## Вывод

Сначала по каждой задаче печатается заголовок с темой, сложностью, типом ответа и
ожидаемым ответом, затем ход прогона. По каждому запросу видно ответ модели,
эталон, время, `effort`, токены `pt`/`ct` и `precached`. В конце — пять таблиц:

* по задачам — четыре знака на строку (по два на каждый уровень: `+` верно,
  `−` неверно, `!` ошибка запроса, `?` нет данных; порядок способов — напрямую,
  пошагово, промпт от модели, эксперты) и счётчик верных ответов;
* по способам решения — сколько верных из скольких по каждому уровню;
* статистика токенов — всего на входе и выходе, сколько переиспользовано из кэша,
  токенов на один верный ответ и на один запрос, а также разбивка по способам,
  уровням, темам задач и сложности, плюс пятёрка самых дорогих запросов;
* диагностика запросов — по каждой ячейке отправленный `effort`, токены
  (`prompt`, `completion`), `precached`, длина цепочки рассуждений и пометка
  «тот же, что у другого уровня»;
* матрица «способ × тема» — какой способ лучше на каком типе задач, с выбором
  лучшего способа в каждой теме по доле верных и ценой в токенах.

После таблиц результаты сохраняются в корне проектов (рядом с `tasks.json`)
в двух файлах с именем `w1t3_<модель>_<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>`:

| Файл | Содержимое |
|---|---|
| `.json` | `meta` (провайдер, модель, время, параметры, итоги), `summary` (срезы по способам, уровням, темам, сложности и матрица способ × тема) и `results` (все запросы построчно) |
| `.csv` | те же строки результатов для Excel и сводных таблиц: разделитель `;`, кодировка `utf-8-sig` |

Путь и имя файлов выводятся в конце прогона.

Токены мета-запросов за промптом входят в ячейку способа «промпт от модели»,
чтобы суммы по таблицам сходились с общим расходом.

### Что отдают API по токенам

| Поле | GigaChat | Veai |
|---|---|---|
| `prompt_tokens`, `completion_tokens`, `total_tokens` | да | да |
| `precached_prompt_tokens` | да | нет |
| `reasoning_content` (цепочка размышлений) | нет | да, отдельным полем |
| токены рассуждений отдельным полем | нет | нет — входят в `completion_tokens` |

Поэтому полный подсчёт расхода возможен у обоих провайдеров
(`prompt + completion`), но доля токенов именно на размышления у обоих
из `usage` не выделяется: у Veai видна только длина `reasoning_content`
в символах, у GigaChat её нет вообще.

### Зачем нужна диагностика

Проверено на GigaChat: ответы не кэшируются, но `usage` содержит
`precached_prompt_tokens` > 0 — API переиспользует **префикс промпта**, а не ответ.
Поэтому столбец `precached` показывает работу этого кэша, а столбец «повтор» —
случаи, где смена уровня не дала вообще никакого эффекта. По GigaChat это
ожидаемо: значения `low`, `medium` и `high` дают одинаковое число токенов ответа,
и параметр не управляет глубиной рассуждений.

В конце — общее число верных ответов и затраченное время.

## Стоимость прогона

12 задач × 8 запросов + 24 запроса за промптом = **120 запросов** на модель.
На Veai это расходует минуты подписки, а прогон на «максимальном» уровне
занимает 10–15 минут реального времени. Сокращённый набор — 7 задач
(70 запросов), примерно вдвое быстрее.

Для отладки приложения используйте GigaChat: ответ идёт 0.1–5 с вместо
4–20 с у Veai. Быстрее всего проверить на 2–3 задачах — создайте временный файл
с нужными задачами из `tasks.json` и передайте его через `--tasks`.

## Известные особенности

* В списке моделей GigaChat есть `Embeddings` (тип не `chat`): список в приложении
  отфильтрован по `type == "chat"`, иначе запрос отвечает `HTTP 404 No such model`.
* `reasoning_effort` у GigaChat принимается, но на ответ не влияет — это
  видно в таблице диагностики по одинаковым ответам и токенам.
* У GigaChat способ «напрямую» даёт очень короткий ответ (2–3 токена), а
  «решай пошагово» — 600–1100 токенов и в разы больше времени.
