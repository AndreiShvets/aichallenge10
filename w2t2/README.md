# w2t2 — агент с памятью разговора

Продолжение [`w2t1`](../w2t1): агент на GigaChat с тремя инструментами, который
теперь помнит разговор. Каждый запрос уходит модели вместе с прошлыми вопрос­ами
и ответами, история сохраняется на диск и переживает выход по `/exit`,
а `/clear` стирает её целиком.

```
запуск → читает history.json (если есть) → запрос пользователя
       → GigaChat (вся история + описание инструментов) → просьба вызвать функцию
       → функция в нашем коде (+ журнал вызовов) → результат обратно модели
       → ответ пользователю → запрос и ответ дописываются в history.json
       → следующий запрос … до /exit
```

Остальное перенесено из `w2t1` без изменений: три инструмента, журнал вызовов,
HTTP-лог, экспорт результатов. Подробности о них — в [`w2t1/README.md`](../w2t1/README.md).

## Память разговора

История — это пары «запрос пользователя → ответ агента». На каждом шаге цикла
модель получает всю историю целиком, поэтому фраза «а если это число умножить
на два?» понимается правильно — речь про результат из прошлого ответа:

```
Запрос: Сколько будет 17 умножить на 23? Ответь одним числом.
Ответ: 391
Запрос: А если это число умножить на 2?
Ответ: 782
```

Что важно в том, как история передаётся:

* в модель уходят только **текстовые** сообщения (`user` / `assistant`);
  просьбы вызвать функцию и их результаты остаются внутри своего цикла —
  иначе на каждый новый вопрос росло бы число лишних сообщений и токенов;
* системная подсказка идёт первой и в файл не пишется: меняющаяся подсказка
  не должна ломать уже сохранённый разговор;
* цена растёт с длиной беседы: входные токены платятся за всю историю на каждом
  шаге цикла. Для длинного разговора это заметно, `/clear` начинает заново.

## Файл истории

По умолчанию `w2t2/history.json`, путь меняется флагом `--history`.
В git файл не попадает: это результат разговора, а не исходник.

```json
{
  "version": 1,
  "started": "2026-11-13 02:57:44 MSK",
  "saved": "2026-11-13 02:57:51 MSK",
  "turns": [
    {
      "at": "2026-11-13 02:57:44 MSK",
      "query": "Сколько будет 17 умножить на 23? Ответь одним числом.",
      "answer": "391",
      "tools": [],
      "steps": []
    },
    {
      "at": "2026-11-13 02:57:51 MSK",
      "query": "Брось игральную кость с 6 гранями.",
      "answer": "4",
      "tools": ["roll_dice"],
      "steps": [
        {"tool": "roll_dice", "arguments": {"sides": 6}, "result": "4", "error": ""}
      ]
    }
  ]
}
```

| Поле | Что значит |
|---|---|
| `version` | версия формата файла |
| `started` | когда начат разговор (меняется после `/clear`) |
| `saved` | когда файл записан последний раз |
| `turns[]` | обмены разговора по порядку |
| `turns[].at` | когда обмен состоялся |
| `turns[].query` | что спросил пользователь |
| `turns[].answer` | что ответил агент (пусто, если ответ не получен) |
| `turns[].tools` | какие инструменты сработали в этом обмене |
| `turns[].steps` | шаги цикла: инструмент, аргументы, результат, ошибка |

Файл пишется целиком после каждого обмена, а не по кусочку: он хранит состояние
разговора, и обрыв на середине записи оставил бы файл наполовину обновлённым.
Если записать не удалось, печатается предупреждение, а разговор продолжается
в памяти до конца сеанса.

## Команды диалога

| Команда | Действие |
|---|---|
| `/exit` | выйти; история остаётся на диске, следующий запуск её подхватит |
| `/clear` | забыть разговор: `history.json` удаляется, беседа начинается заново |
| пустая строка | пропускается |

Конец ввода (`Ctrl+D`, `Ctrl+Z` в Windows) работает так же, как `/exit`.

## Прогон и проверка

```powershell
python .\w2t2\main.py
```

Что проверить:

1. **История внутри сеанса.** Ввести «Сколько будет 17 умножить на 23? Ответь
   одним числом.», затем «А если это число умножить на 2?» — второй ответ
   должен опираться на первый (391 → 782).
2. **История между запусками.** Выйти по `/exit`, запустить снова: печатается
   «Продолжается разговор из N обменов», и следующий вопрос продолжает тему.
3. **Инструменты помнят свой вызов.** «Брось игральную кость с 20 гранями»
   и следом «А теперь переведи выпавшее число в шестнадцатеричную» — агент
   берёт число из прошлого ответа без повторного броска.
4. **`/clear`.** После команды печатается «История разговора очищена», файл
   исчезает, а вопрос про предыдущие числа больше не имеет контекста.

Посмотреть, что именно уходило модели, можно в `w2t2/http.log`: в
`request_body.messages` на каждом шаге видны все прошлые пары сообщений
(команда для быстрого чтения — в [`w2t1/README.md`](../w2t1/README.md)).

Флаги запуска:

| Флаг | Действие |
|---|---|
| `--history PATH` | другой файл истории разговора |
| `--model NAME` | другая модель GigaChat (по умолчанию самая дешёвая, `GigaChat`) |
| `--log PATH` | другой журнал вызовов инструментов |
| `--http-log PATH` | другой HTTP-лог диалога с моделью |
| `--env PATH` | файл с ключом |
| `--no-cache` | переавторизоваться, минуя кэш токена |

## Ловушки

* **Битый `history.json` — ошибка, а не тихая потеря.** Если файл не читается
  или в нём нет `turns`, программа сообщает об этом и подсказывает удалить файл
  или ввести `/clear`; молча начинать разговор заново нельзя — пользователь
  решил бы, что память пропала сама.
* **История без результата.** Если лимит шагов исчерпан и ответа нет, в историю
  попадает только запрос: придумывать ответ ассистента нельзя, иначе модель
  получит в контексте текст, которого она не говорила.
* **Номер запроса в HTTP-логе — это номер в сеансе,** а не в разговоре:
  после перезапуска нумерация начинается с 1, а `history.json` продолжается.
  Какая история была в контексте, видно по самим `messages` в запросе.
* **`/clear` не стирает журналы.** `tool_calls.log` и `http.log` — это следы
  работы для разбора; если нужна полная чистота, удаляются и они.
