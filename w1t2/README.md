# w1t2 — запрос к GigaChat или шлюзу Veai

Развитие [w1t1](../w1t1): вместо простого вывода списка моделей и баланса —
интерактивный запрос к двум провайдерам на выбор.

## Что делает

1. Запрашивает список моделей у GigaChat и у шлюза Veai и печатает обе таблицы.
   Если один провайдер недоступен, второй всё равно используется.
2. Для GigaChat дополнительно показывает остаток токенов (если он включён в тарифе).
3. Просит ввести текст запроса (пустая строка завершает ввод).
4. Спрашивает четыре необязательных параметра (пропускаются пустой строкой):
   1. явное описание формата ответа;
   2. ограничение объёма ответа в токенах (`max_tokens`);
   3. stop sequence (одна или несколько через запятую);
   4. строгая JSON-схема — поля видом `name:type[:описание]`.
5. Спрашивает провайдера: GigaChat или Veai.
6. Печатает модели выбранного провайдера, в которые можно отправить текстовый
   запрос, и просит выбрать модель — номером или точным id.
7. Выполняет **четыре прогона** одного запроса и для каждого печатает ответ,
   токены и проверку на валидность JSON:

| Прогон | Ограничения (max_tokens, stop) | Строгая схема |
|---|---|---|
| 1 | нет | нет |
| 2 | да | нет |
| 3 | нет | да |
| 4 | да | да |

Описание формата ответа попадает в промпт всех прогонов, иначе сравнивать
проверку JSON между прогонами бессмысленно.

Где провайдер не поддерживает смысл параметра, прогон **не отправляется**, и вместо
ответа печатается «Не поддерживается» с причиной. Если же параметр принимается,
но не применяется, прогон отправляется, а после ответа печатается предупреждение
с пометкой, что сработало, а что — нет.

## Что поддерживается на самом деле

Проверено запросами к API, а не только по документации:

| Параметр | GigaChat | Veai |
|---|---|---|
| Описание формата в промпте | работает | работает |
| `max_tokens` | работает (`finish_reason: length`) | работает |
| `stop` | принимает, но **не применяет** — ответ не обрывается, хотя `finish_reason: stop` | работает, но зависит от модели (у DeepSeek не сработал) |
| Строгая JSON-схема | не поддерживается в `v1` на тарифе физлиц, схема описана для `v2` (B2B) | работает: `json_schema` + `strict: true` |

Следствия, которые видны в выводе программы:

* На GigaChat прогоны 3 и 4 «Не поддерживается» — схема не передаётся вообще.
* Прогоны 2 и 4 на GigaChat отправляются вместе со stop, но после ответа программа
  предупреждает, что stop не применён: ответ обрезал только `max_tokens`, и в выводе
  это видно по `finish_reason: length` (при нехватке лимита) или `stop` (когда текст
  закончился сам).
* GigaChat оборачивает JSON в markdown-блок ```` ```json ````, поэтому проверка
  честно говорит «Нет: Expecting value» и указывает причину. Это и есть ответ
  на вопрос «валидный ли JSON».
* У Veai `response_format: json_object` без схемы отклоняется с `HTTP 400`,
  поэтому в запрос всегда идёт `json_schema`.

## Отличия провайдеров

| | GigaChat | Veai |
|---|---|---|
| Авторизация | OAuth по ключу, токен кэшируется на 30 минут | API-ключ в каждом запросе |
| Список моделей | `GET /api/v1/models`, фильтр `type == "chat"` | `GET /openai/api/models`, фильтр по текстовым модальностям (35 моделей) |
| Запрос | `POST /api/v1/chat/completions` | `POST /openai/api/v1/chat/completions` (OpenAI-совместимый) || Сертификаты НУЦ Минцифры | нужны (лежат в `certs/`) | не нужны |

Документация Veai: <https://veai.ru/docs/veai/connect/api>

## Подготовка

В `.env` (тот же файл, что у w1t1 — ищется от папки задачи вверх по дереву)
нужны два ключа:

```
GIGACHAT_CREDENTIALS=<ключ авторизации GigaChat>
VEAI_CREDENTIALS=<персональный API-ключ Veai>
```

Образец — [`.env.example`](.env.example).

## Запуск

```powershell
python .\w1t2\main.py
```

Флаги те же, что у w1t1:

```powershell
python .\w1t2\main.py --env D:\projects\ai\.env   # указать файл ключей явно
python .\w1t2\main.py --no-cache                  # переавторизоваться в GigaChat, минуя кэш токена
```

Код возврата: `0` — ответ получен, `1` — ошибка (нет ключа, отказ авторизации,
нет сети, неверный ввод).

Внешние зависимости не нужны. Кэш токена GigaChat хранится в `w1t2/.cache/`.
