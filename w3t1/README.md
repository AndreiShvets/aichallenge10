# w3t1 — явная модель памяти ассистента

Продолжение [`w2t5`](../w2t5): тот же агент с инструментами, но информация
разложена по трём слоям памяти с отдельными хранилищами, правилами записи
и правилами отбора в промпт.

## Слои

| Слой | Что лежит | Где хранится | Правило отбора в промпт |
|---|---|---|---|
| краткосрочная | обмены текущего диалога (механизм `w2t2`) | `history.json` + `summary.json` | сводка сжатого + последние `--keep N` обменов |
| рабочая | данные текущей задачи: срок, бюджет, ограничение, встреча, регион | `work.json` | последние 24 записи, новые выше |
| долговременная | профиль, решения, знания: имя, решение, формат, знания | `long.json` | последние 12 записей, новые выше |

Слои физически разделены: рабочая и долговременная память — два файла с
независимым форматом, история разговора осталась в `history.json` из `w2t2`.
Каждая запись памяти помнит источник — правило, модель или явную команду.

## Что и куда записывается

Три источника, все видимы в `/memory`:

1. **Правила** (`update_facts`) — те же шаблоны, что в `w2t5`, но с раскладкой
   по слоям: срок, бюджет, ограничение, встреча и регион → рабочая;
   имя, решение и формат → долговременная.
2. **Модель** (`extract_facts`) — на каждый обмен один запрос с просьбой
   вернуть JSON `{"facts": [{"layer": "long|work|short", "key", "value"}]}`.
   Слой `short` отдельного файла не получает: эти подробности и так лежат
   в обменах. Отключается флагом `--no-extract`.
3. **Явно** — `/remember ключ=значение [long|work]`; без слоя слой выбирается
   по правилу ключа (данные задачи → рабочая, остальное → долговременная).

## Смена задачи

Определяется гибридным детектором на каждом сообщении:

- правила сравнивают значимые слова нового запроса с предыдущим: общие слова —
  та же задача, ни одного общего — новая, мало слов — решает модель;
- модель спрашивают только в сомнительном случае, ответ сохраняется
  в журнале словами («модель: новая задача» / «правило: нет общих слов»);
- `--rules-only` отключает запрос к модели совсем.

При смене задачи рабочая память **уходит в архив** (`archive` в `work.json`),
долговременная остаётся, краткосрочная история начинается заново.
Явные способы: `/task NAME` — новая задача, `/task open N` — вернуться
к архивной (её рабочая память снова становится текущей), `/task` — обзор.

## Состав и стоимость слоёв

- `/memory` — что лежит в каждом слое, чем он отдаётся в промпт и сколько
  занимает; источник каждой записи;
- `/limits` — вклад каждого слоя в токены запроса одной таблицей;
- локальная ошибка одного извлечения не роняет прогон: факты просто
  не пополняются, причина пишется в вывод.

## Опыт с очисткой слоёв

`/cleanup` — протокол из задания: четыре состояния, в каждом те же вопросы
из `details.json` (8 контрольных деталей Дня 10).

| Состояние | Долговременная | Рабочая | Краткосрочная |
|---|---|---|---|
| `all` | вкл | вкл | вкл |
| `-long` | выкл | вкл | вкл |
| `-work` | выкл | выкл | вкл |
| `-short` | выкл | выкл | выкл |

В каждом состоянии создаётся независимая копия памяти, и очищенный слой
фактически удаляется из неё: для краткосрочного слоя используется пустая
история, для рабочего и долговременного — пустое хранилище. Исходные файлы
и память основной сессии не меняются, поэтому опыт можно повторить без
восстановления данных. Заглушки в очищенные слои не добавляются.

Автосжатие и извлечение на время опыта отключаются — иначе различия
по токенам смешались бы с лишними запросами.

Результат: `cleanup.json` (по состояниям), `/compare` печатает таблицу
«деталь × состояние» и «из памяти / догадка / НЕТ ДАННЫХ» по состояниям.

Проверочные вопросы идут в строгом режиме: модель получает инструкцию
отвечать только по переданным блокам и возвращать ровно `НЕТ ДАННЫХ`, если
факта нет. Для каждой строки дополнительно фиксируется происхождение:
`memory` — ожидаемое значение найдено в переданном слое, `guess` — модель
назвала правильное значение, но его не было в контексте, `no_data` — модель
отказалась отвечать, `other` — ответ не совпал с эталоном. Поэтому «найдено»
в сводке означает только `memory`, а догадки не засчитываются.

Порядок очистки (`all → -long → -work → -short`) — согласованный вариант:
первым убирается то, что переживает задачи, последним — сам диалог.

## Команды и параметры

| Команда/параметр | Назначение |
|---|---|
| `/memory` | состав всех трёх слоёв и их вклад в промпт |
| `/remember ключ=значение [long\|work]` | явная запись в слой |
| `/forget ключ [long\|work]` | удалить запись |
| `/task [NAME \| open N]` | новая задача, возврат к архивной, обзор |
| `/cleanup` | опыт: 4 состояния × вопросы из `details.json` |
| `/compare` | сводка опыта из `cleanup.json` |
| `/check` | вопросы из `details.json` без изменения слоёв |
| `/limits` | вклад слоёв, сжатие и расход сеанса |
| `/clear` | забыть разговор: история и сводка удаляются, задача закрывается |
| `/clear-layer short\|work\|long` | физически стереть один слой; остальные не трогаются. `work` включает архив задач, `long` очищается целиком |
| `/compress [N]`, `/fill [N]`, `/checkpoint`, `/branch`, `/switch`, `/help` | как в `w2t5` |
| `--work PATH`, `--long PATH` | файлы рабочей и долговременной памяти |
| `--no-extract` | извлечение фактов моделью выключено |
| `--rules-only` | смену задачи решают только правила |

Остальные параметры (`--model`, `--limit`, `--keep`, `--every`, `--history`,
`--summary`, журналы, авторизация) работают как в [`w2t5/README.md`](../w2t5/README.md).

## Ввод команд

По умолчанию Tab дополняет команды в терминалах, где доступен `readline`.
Если модуль недоступен (обычно в стандартном Python для Windows), используйте
полные команды или включите режим сокращений:

```powershell
python .\w3t1\main.py --command-prefix
```

В этом режиме однозначные сокращения раскрываются после Enter: например,
`/mem` означает `/memory`. При нескольких совпадениях показываются варианты;
неизвестная slash-команда не отправляется модели. Tab-дополнение в этом режиме
не включается.

## Провайдеры и модели

По умолчанию используется GigaChat:

```powershell
python .\w3t1\main.py
```

Veai включается явно; `--model` принимает идентификатор модели из каталога Veai:

```powershell
python .\w3t1\main.py --provider veai --model openai/gpt-4o-mini
```

Ключи читаются из `.env`: `GIGACHAT_CREDENTIALS` для GigaChat и
`VEAI_CREDENTIALS` для Veai. У Veai режим инструментов не используется:
провайдер вызывается как OpenAI-compatible текстовая модель, но модельное
извлечение фактов и распределение по слоям работает одинаково.

Для списка OpenAI-моделей в Veai:

```powershell
python .\w3t1\compare_layers.py --list-veai
```

Сравнительный прогон одинаковых 30 фраз на нескольких моделях:

```powershell
python .\w3t1\compare_layers.py --models gigachat:GigaChat,gigachat:GigaChat-Max,veai:MODEL_SIMPLE,veai:MODEL_STRONG
```

Результат сохраняется в `w3t1_layer_compare.json`.

## Запуск

```powershell
python .\w3t1\main.py                       # интерактивно
python .\w3t1\main.py --rules-only           # без запроса про смену задачи
python .\w3t1\main.py --no-extract           # только правила и /remember
```

Локальная проверка без модели подменяет `main.run_agent`/`chat_messages`
заглушкой: так проверены раскладка по слоям, фактическое удаление копии,
отбор в промпт, вклад токенов, опыт с очисткой и файлы памяти.

## Цена

Каждый обмен даёт до двух лишних запросов: извлечение фактов моделью
и, в сомнительном случае, определение смены задачи. В опыте `/cleanup` это 4 состояния × 8 вопросов; очищенная
краткосрочная память передаётся как пустая история, без запроса-заглушки.

Реальные прогоны требуют времени и денег: тяжёлые сценарии запускаются только
после согласования.

## Экспорт

После выхода в корне рядом с `tasks.json` появляются
`w3t1_<модель>_<ГГГГ-ММ-ДД>_<ЧЧ-ММ-СС>.json` и `.csv`. Итог диалога
печатает состав каждого слоя.
