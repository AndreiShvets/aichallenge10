# w3t2 — персонализированный агент

Продолжение [w3t1](../w3t1/README.md): агент сохраняет профиль пользователя отдельно от краткосрочной, рабочей и долговременной памяти и передаёт его вместе с ними при ответе. Профиль не вытесняется ограничением числа фактов долговременной памяти и сохраняется при смене задачи.

## Запуск

```powershell
python .\w3t2\main.py
python .\w3t2\main.py --provider veai --model openai/gpt-4o-mini
```

Настройка ключей и остальные параметры описаны в [w3t1](../w3t1/README.md). При старте выбирается профиль `default`. История, сводка, рабочая и долговременная память и ветки хранятся отдельно в `w3t2/profiles/<имя>/`; параметры путей `--history`, `--summary`, `--work`, `--long`, `--branches` несовместимы с профилями и не принимаются.

## Ввод команд

По умолчанию в поддерживающих `readline` терминалах Tab дополняет команды и их подкоманды. Если `readline` недоступен (например, в стандартной установке Python для Windows), остаётся обычный ввод полной команды.

Для раскрытия сокращений после Enter запустите агент с флагом `--command-prefix`:

```powershell
python .\w3t2\main.py --command-prefix
```

Например, `/prof sel` означает `/profile select`. Если сокращение неоднозначно, программа покажет варианты; неизвестная команда не отправляется модели. В этом режиме дополнение по Tab не включается.

## Профили

- `/profile` — показать активный профиль.
- `/profile list` — показать список профилей и отметить активный.
- `/profile select` — показать список и выбрать профиль по номеру; Enter отменяет выбор.
- `/profile use ИМЯ` — создать или переключить профиль; имя состоит из латинских букв, цифр, `_` и `-`.
- `/profile set style=кратко и неформально` — задать стиль.
- `/profile set format=без кода` — задать формат.
- `/profile set constraints=без жаргона` — задать ограничения; пустое значение очищает поле.

Профиль пополняется из явно выраженных постоянных предпочтений в диалоге, например «Всегда отвечай подробно и формально». При включённом извлечении модель дополнительно разбирает свободные формулировки до ответа, что требует отдельного запроса на каждую реплику. `--no-extract` отключает этот запрос; остаются ограниченные правила. Одноразовые пожелания не предназначены для сохранения в профиль. Переключение профиля также переключает его память и историю. `/clear` и смена задачи не удаляют профиль.

## Проверка персонализации

Команда `/personal-test` после подтверждения запускает опыт: два противоположных профиля отвечают на одинаковый вопрос, затем краткий профиль отвечает на десять разных вопросов подряд в одном диалоге. Опыт изолирован от пользовательских профилей и памяти. Он делает минимум 12 платных запросов; фактическое число и стоимость зависят от модели и провайдера.

Для каждого ответа вручную отмечаются длина, тон и наличие кода: соблюдено, нарушено или не определено. Полные ответы, критерии, оценки и ошибки записываются в JSON и CSV в корне репозитория. Вывод показывает число ответов, где соблюдены все предпочтения, и первый обнаруженный номер нарушения. Если до него есть ошибка или неопределённая оценка, точный номер первого нарушения неизвестен. Обрезанный ответ (`finish_reason=length`) считается ошибкой, а не успешной проверкой.

Ручная оценка субъективна: краткость, подробность и тон следует оценивать одинаково для всех ответов. Проверка на заглушках подтверждает работу программы, но не соблюдение предпочтений реальной моделью.
