# w4t2 — свой MCP-сервер: первый инструмент

Продолжение [`w4t1`](../w4t1): там агент подключался к чужому MCP-серверу
(filesystem) по stdio. Здесь — наоборот: сами пишем MCP-сервер вокруг
mock-трекера задач и подключаем его к агенту по HTTP.

```
агент (GigaChat + decimal_to_hex) ──HTTP POST /mcp──> server.py (mock-tracker)
     │ tools/list → схемы list_tasks, get_task, create_task → в массив functions
     │ модель выбирает инструмент → tools/call → текст результата обратно модели
```

## Состав

| Файл | Что делает |
|---|---|
| `tracker.py` | mock-трекер: пять задач в памяти, список и поиск по статусу, создание задачи |
| `server.py` | MCP-сервер поверх HTTP: `initialize`, `tools/list`, `tools/call`; регистрация инструментов и их JSON-схем |
| `mcp_http_client.py` | клиент MCP поверх HTTP (тот же протокол, что в w4t1, другой транспорт) |
| `main.py` | агент из w4t1 без filesystem: локальный `decimal_to_hex` + инструменты трекера |
| `test_tracker_server.py` | 15 проверок: трекер, обработчики протокола, HTTP-клиент против живого сервера |
| `gigachat_client.py`, `certs/` | копии из w4t1 |

## Инструменты

| Инструмент | Входные параметры | Что возвращает |
|---|---|---|
| `list_tasks` | `status`: `open` / `in_progress` / `done`, необязательно | список задач (JSON-текст) |
| `get_task` | `key`, например `TR-2`, обязательно | одна задача |
| `create_task` | `summary` обязательно; `assignee`, `priority` (`low`/`normal`/`high`) необязательно | созданная задача с новым ключом, статус `open` |

Регистрация — в `server.py`, список `TOOLS`: имя, описание для модели и
`inputSchema` в JSON Schema. Обработчик хранится рядом, но в `tools/list`
не уходит. Ошибка предметной области (нет задачи, неверный статус) возвращается
результатом с `isError: true` — модель видит текст и выбирает другой путь;
ошибка протокола (неизвестный метод, неверные параметры) — JSON-RPC `error`.

## Запуск

```powershell
python .\w4t2\server.py --port 8765                  # в отдельном окне, оставить запущенным
python .\w4t2\main.py --list-tools                   # проверка связи, без модели
python .\w4t2\main.py                                # интерактивно, смешанный набор
python .\w4t2\main.py --mcp-url http://127.0.0.1:8765/mcp
```

Без запущенного сервера агент не стартует и говорит, что нужно выполнить
`python server.py`.

## Проверки

Без модели и без сети:

```powershell
python -m unittest discover -s w4t2 -p "test_*.py" -v
```

Проверено: фильтр и создание в трекере, `initialize`, `tools/list` без
обработчиков, `tools/call` с текстом результата, ошибка инструмента как
результат, неизвестный метод как ошибка протокола, уведомления без ответа,
HTTP-клиент против сервера в том же процессе.

Ручная проверка связи выполнена: `--list-tools` получил три инструмента
сервера `mock-tracker 0.1.0`.

## Ответы на вопросы задания

**Как регистрируется инструмент?** Записью в `TOOLS` (`server.py`): имя,
описание, `inputSchema`, обработчик. Ответ на `tools/list` строится из этих
записей. Добавить инструмент — дописать запись; клиент и агент не меняются.

**Как описываются входные параметры?** JSON Schema в `inputSchema`:
типы, `required`, `enum` для статуса и приоритета. Описания полей пишутся
для модели — по ним она заполняет аргументы.

**Что возвращается?** Текстовый блок `content` с JSON внутри строки. Модель
получает его как результат функции и формулирует ответ пользователю.

## Живой прогон

Запрос «Покажи задачу TR-2 и скажи, кто её исполнитель» на GigaChat:

```text
шаг 1: [mcp] get_task({"key": "TR-2"}) → {"key": "TR-2", ..., "assignee": "Петров", ...}
Ответ: Исполнитель задачи TR-2 — Петров.
```

Модель выбрала инструмент сама по описанию из `tools/list`, передала аргумент
`key` и использовала результат в ответе. Два запроса к модели, 947 токенов
входа и 39 выхода.

Запуск: сначала `python server.py` в отдельном окне, затем `python main.py`.
