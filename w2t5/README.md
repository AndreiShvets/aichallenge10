# w2t5 — сравнение стратегий управления контекстом

Продолжение [`w2t4`](../w2t4): агент с теми же инструментами, историей,
токенами и сжатием, но теперь можно сравнить три стратегии памяти.

## Стратегии

| Стратегия | Что отправляется модели |
|---|---|
| `sliding` | только последние `--window N` обменов; старые полностью отбрасываются из контекста |
| `facts` | блок Sticky Facts (ключ–значение) + последние `--window N` обменов |
| `summary` | сводка старых обменов + последние `--keep N`; стратегия из w2t4 |

Переключатель — `--strategy summary|sliding|facts`. Для контрольного запуска
без сжатия можно использовать `--strategy sliding --window 4` или старый алиас
`--no-compress`. История на диске при этом не теряется: sliding отбрасывает
старые сообщения только из запросов модели.

### Sticky Facts

При каждом сообщении пользователя перед запросом обновляется словарь фактов.
В учебном сценарии извлечение детерминированное и не требует отдельного
вызова модели: распознаются фразы про срок, бюджет, ограничение, имя,
решение, формат, регион и встречу. Факты сохраняются в `history.json` и
передаются отдельным блоком перед живым окном. Это позволяет сравнить
стоимость и воспроизводимость key-value-памяти с модельным summary.

## Проверка деталей

`details.json` — восемь контрольных фактов из задания Дня 9: срок, бюджет,
ограничение, имя, решение, формат, регион и встреча. После диалога на 20–30
сообщений команда `/check` задаёт вопросы по каждому факту и выводит таблицу
«ожидалось / ответ / помнит». Проверка не вызывает модель-судью: точное и
частичное совпадение определяются локально. Ответы и расходы сохраняются в
`checks.json` по ключу стратегии.

Сравнить три режима на одинаковом сценарии:

```powershell
python .\w2t5\main.py --strategy sliding --window 4 --history sliding.json
python .\w2t5\main.py --strategy facts --window 4 --history facts.json
python .\w2t5\main.py --strategy summary --keep 4 --every 5 --history summary.json
```

В каждом запуске введите одинаковые 20–30 сообщений с деталями и затем
`/check`. Команда `/compare` читает накопленный `checks.json` и печатает:
стратегию, количество найденных деталей и входные токены вопросов.
Реальный прогон такого размера дорогой — запускать только после согласования;
локально проверяйте на заглушке.

## Ветвление диалога

- `/checkpoint NAME` сохраняет снимок текущей истории;
- `/branch NAME` создаёт независимую ветку от текущей точки;
- `/switch NAME` переключает активную историю на ветку;
- снимки сохраняются отдельными файлами рядом с `--branches PATH`, по умолчанию
  `branches_NAME.json`. После переключения новые сообщения меняют только
  активную ветку.

Пример:

```text
/checkpoint plan
/branch optimistic
/branch conservative
/switch optimistic
# продолжение A
/switch conservative
# продолжение B
```

## Команды и параметры

| Команда/параметр | Назначение |
|---|---|
| `/limits` | размер текущего контекста, окно, facts/summary и расход |
| `/check` | проверить восемь контрольных деталей |
| `/compare` | таблица результатов стратегий из `checks.json` |
| `/compress [N]` | ручное сжатие для `summary` |
| `/checkpoint NAME` | сохранить checkpoint |
| `/branch NAME` | сохранить ветку от текущей точки |
| `/switch NAME` | переключиться на ветку |
| `/clear` | удалить историю и summary |
| `/help` | полная справка |
| `--strategy NAME` | `summary`, `sliding` или `facts` |
| `--window N` | размер окна для sliding/facts |
| `--keep N` | размер живого хвоста для summary |
| `--every N` | порог автоматического summary |
| `--no-compress` | алиас sliding |
| `--history PATH` | файл полной истории |
| `--summary PATH` | файл summary |
| `--branches PATH` | префикс файлов checkpoint/веток |

Остальные параметры (`--model`, `--limit`, `--fill`, журналы и авторизация)
работают как в [`w2t4/README.md`](../w2t4/README.md).

## Экспорт и токены

После выхода экспорт создаётся в корне как `w2t5_<модель>_...json/csv`.
`/limits` показывает текущую оценку входа и сравнение стратегий: у sliding
стоимость контекста ограничена окном, у facts добавляется небольшой блок
фактов, у summary добавляется размер сводки. Входные токены — реальный расход,
оценка контекста — локальное приближение.

Реальные модели требуют времени и денег: тяжёлые прогоны, полные сценарии
20–30 сообщений и большие проверки запускаются только после согласования.
